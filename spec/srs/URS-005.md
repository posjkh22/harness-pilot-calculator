## 1. 원본 사용자 요구사항 요약

제수가 0인 모든 나누기 계산에서 피제수와 무관하게 결과 대신 정확히 Error를 표시한다.

| AC ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-URS-005-01 | 피제수가 0 또는 0이 아닌 값이고 나누기 연산자와 제수 0이 입력되어 있을 때 | 사용자가 등호 버튼을 누르면 | 피제수가 0인 0 ÷ 0을 포함하여 제수가 0인 모든 계산에서 디스플레이에 정확히 "Error"가 표시되고 숫자 계산 결과는 표시되지 않아야 한다. |

## 2. 기술 명세

### SRS-URS-005-01 (renderer/ui)

**명세**: 나누기 연산의 오른쪽 피연산자가 숫자 0이면 피제수가 0인지 여부와 관계없이 실제 나눗셈을 수행하지 않고 display에 대소문자와 철자가 정확히 "Error"를 표시해야 한다.

**근거**: 0 ÷ 0을 포함한 모든 0 나누기를 동일하게 처리해야 한다.

| 항목 | 값 |
| --- | --- |
| 검증 대상 AC | AC-URS-005-01 |
| 검증 전략 | UNIT |
| 변경 예상 파일 | ui/calculator.js, tests/calculator.test.js, tests/calculator.ui.test.js |
| 테스트 훅 | Unit-test both 0 ÷ 0 and nonzero ÷ 0., UI-test the display for exact text equality with "Error" and assert it is not Infinity or NaN., Expose the display through data-testid="display". |

**인터페이스 계약**

| 유형 | 이름 | 방향 | 요청 | 응답 | 오류 | 권한 |
| --- | --- | --- | --- | --- | --- | --- |
| MODULE | calculatorState.evaluateDivision | INTERNAL | { dividend: numeric input, divisor: numeric input } | "Error" when divisor === 0; otherwise the division result | Non-numeric operands are rejected.; The zero-divisor branch must prevent numeric division. | Renderer-local calculation function. |
| EVENT | zero-division-result | INTERNAL | Equals action with operator "/" and right operand 0 | Display text exactly "Error" and numeric result is absent | Any numeric display for a zero divisor is a test failure. | Renderer-local event only. |

**데이터 모델**

- dividend: numeric value, including 0.
- divisor: numeric value.
- error display sentinel: exact string "Error".
- Evaluation status distinguishes error from numeric result.

**오류 처리**

- Check divisor === 0 before division.
- Set the display to exactly "Error" for 0 ÷ 0 and nonzero ÷ 0.
- Do not expose Infinity, NaN, or a numeric result for a zero divisor.

**보안**

- Use explicit numeric comparison and operator dispatch; never evaluate a constructed expression.
- The fixed Error sentinel is assigned through textContent.

**성능·운영**

- Zero-divisor detection is an in-memory branch completed during the equals event.
- No retry, persistence, or external service is involved.

## 4. 마이그레이션·호환성

- 신규 계산 동작이므로 기존 오류 표시 계약과의 호환성 변경은 없다.
- Error 문자열은 수용 기준의 외부 관찰 계약으로 유지한다.

## 5. 구현 순서

1. 나눗셈 계산 전에 제수의 숫자 0 여부를 검사한다.
2. Error 상태와 정확한 표시 문자열을 구현한다.
3. 0 ÷ 0 및 비영 피제수 ÷ 0 단위/UI 테스트를 추가한다.

## 6. 위험·제외·미결정

**위험**

- 후속 요구에서 오류 해제 또는 오류 이후 입력 동작을 정의하면 상태 전이 변경이 필요하다.
- 숫자 파싱 정책이 바뀌면 0 판정 경계도 함께 재검증해야 한다.

**제외 범위**

- 0으로 나누기 이후의 추가 입력 동작
- 오류 해제 UX
- NaN, Infinity 등 기타 비정상 수식의 상세 표시 정책
