## 2. 기술 명세

### SRS-URS-002-01 (renderer/ui)

**명세**: 계산기 화면은 계산기 화면은 숫자 0부터 9까지 각각 하나씩, 더하기·빼기·곱하기·나누기 버튼, 등호 버튼, 초기화 버튼을 제공해야 하며 각 버튼은 고유한 접근 가능한 이름과 동작 식별자를 가져야 한다.

**근거**: 사용자가 계산에 필요한 모든 입력 및 제어 요소를 확인하고 선택할 수 있어야 한다.

| 항목 | 값 |
| --- | --- |
| 검증 대상 AC | AC-URS-002-01 |
| 검증 전략 | UI_INTEGRATION |
| 변경 예상 파일 | ui/index.html, ui/styles.css, ui/calculator.js, tests/calculator.test.js, tests/electron.integration.test.js |
| 테스트 훅 | Use data-testid values digit-0 through digit-9, operator-add, operator-subtract, operator-multiply, operator-divide, equals, and clear., Provide accessible button text or aria-label values matching the action., Count and identify all required buttons in the UI integration test. |

**인터페이스 계약**

| 유형 | 이름 | 방향 | 요청 | 응답 | 오류 | 권한 |
| --- | --- | --- | --- | --- | --- | --- |
| MODULE | Calculator UI button set | INTERNAL | DOM click events for digit, operator, equals, and clear buttons | The corresponding calculator action is dispatched to the renderer state machine | Unknown action identifiers are rejected and logged during development.; Missing required buttons fail the UI integration test. | Renderer-local event handling; no privileged API access. |

**데이터 모델**

- Digit actions: 0 through 9.
- Operator actions: +, -, *, /.
- Control actions: = and clear.
- Each button has a stable data-testid and accessible label.

**오류 처리**

- A missing or duplicated required button is a test failure rather than silently ignored.
- Unexpected action values do not mutate calculator state.

**보안**

- Button handlers remain in the isolated renderer context.
- No button action evaluates arbitrary JavaScript or accepts executable input.

**성능·운영**

- All 16 required buttons are present after the initial local document load.
- Click handling is local and completes within the same renderer event cycle.

## 4. 마이그레이션·호환성

- 신규 UI이므로 기존 화면 또는 DOM 계약과의 호환성 변경은 없다.
- 버튼 식별자는 테스트와 자동화의 계약으로 취급하고 이후 변경 시 호환성을 유지한다.

## 5. 구현 순서

1. HTML에 display와 16개 버튼을 선언한다.
2. 각 버튼에 고유한 data-testid와 접근 가능한 텍스트를 부여한다.
3. renderer 이벤트 위임 또는 개별 핸들러를 연결한다.
4. UI 통합 테스트에서 버튼 수, 종류, 식별자를 검증한다.

## 6. 위험·제외·미결정

**위험**

- 버튼 텍스트만 변경하면 자동화 식별자가 깨질 수 있으므로 data-testid를 안정적으로 유지해야 한다.
- 곱하기와 나누기 기호의 표시 문자가 내부 연산자 값과 혼동되지 않도록 별도 매핑을 둔다.

**제외 범위**

- 버튼의 시각적 디자인, 크기, 배치
- 키보드 입력, 마우스 이외의 입력 방식
- 계산기 이외의 UI 화면
