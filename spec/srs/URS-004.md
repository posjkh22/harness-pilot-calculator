## 1. 원본 사용자 요구사항 요약

두 숫자와 하나의 사칙연산자를 입력하고 등호를 누르면 해당 계산 결과를 디스플레이에 표시한다.

| AC ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-URS-004-01 | 두 숫자와 하나의 사칙연산자가 입력되어 있을 때 | 사용자가 등호 버튼을 누르면 | 입력된 두 숫자와 연산자에 따른 계산 결과가 디스플레이에 표시되어야 한다. |

## 2. 기술 명세

### SRS-URS-004-01 (renderer/ui)

**명세**: renderer는 첫 번째 숫자, 하나의 사칙연산자, 두 번째 숫자를 순서대로 수집하고 등호 클릭 시 해당 두 피연산자와 연산자를 계산하여 결과를 display에 표시해야 한다.

**근거**: 기본 사칙연산의 결과를 사용자가 확인할 수 있어야 한다.

**인터페이스 계약**

| 유형 | 이름 | 방향 | 요청 | 응답 | 오류 | 권한 |
| --- | --- | --- | --- | --- | --- | --- |
| MODULE | calculatorState.evaluate | INTERNAL | { left: numeric input, operator: "+"\|"-"\|"*"\|"/", right: numeric input } | Numeric result formatted as a display string | Incomplete expression is rejected.; Unknown operator is rejected.; Division with a zero right operand produces the Error state defined by URS-005. | Renderer-local calculation function; no privileged access. |
| EVENT | equals-click | INTERNAL | DOM click event from the equals button | Display is updated to the computed result or Error | Invalid expression must not produce a numeric result.; Calculation failures transition to a visible error state. | Renderer-local event only. |

**데이터 모델**

- Expression state: left operand, operator, right operand, and evaluation status.
- Supported operators are exactly +, -, *, /.
- Results are displayed as text; complex precedence, decimals, and rounding are not required by this requirement.

**오류 처리**

- The equals action validates that both operands and exactly one supported operator are present.
- Invalid or incomplete input is surfaced through the display error state and does not throw an uncaught renderer exception.
- A zero divisor is handled before numeric division and produces exactly "Error".

**보안**

- Calculation uses explicit operator dispatch rather than eval or Function.
- Operands are parsed from controlled numeric state, not executed as code.

**성능·운영**

- Evaluation is an in-memory operation with no I/O.
- The display update occurs in the same user interaction cycle.

## 4. 마이그레이션·호환성

- 신규 계산 상태 모델이므로 기존 계산 API 또는 저장 데이터와의 호환성 변경은 없다.
- 연산자 처리 계약은 renderer 내부에 한정하며 외부 IPC/HTTP 계약을 만들지 않는다.

## 5. 구현 순서

1. 입력 상태에 두 피연산자와 연산자를 저장한다.
2. 사칙연산별 명시적 계산 분기를 구현한다.
3. 등호 처리에서 입력 완전성을 검증한다.
4. 계산 결과 표시와 단위/UI 테스트를 구현한다.

## 6. 위험·제외·미결정

**위험**

- 소수점, 반올림, 큰 수 및 표시 형식은 요구에서 제외되어 결과 표현에 후속 결정이 필요할 수 있다.
- 연속 계산과 연산자 변경 동작은 요구되지 않아 구현 범위를 확장하면 상태 전이가 복잡해질 수 있다.

**제외 범위**

- 연산자 우선순위가 필요한 복합 수식
- 소수점 입력, 반올림 및 결과 표시 형식
- 메모리 연산과 연속 계산

**미결정 사항**

- 결과의 숫자 형식과 부동소수점 정밀도 정책은 후속 요구에서 결정해야 한다.
